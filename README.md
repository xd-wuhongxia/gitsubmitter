# Git统计分析仪表板

一个基于 Streamlit 的 Git 仓库统计分析工具，提供全面的提交历史、合并历史和代码贡献分析。

## 功能特性

### 📊 核心功能
- **提交历史分析** - 详细的提交统计和时间线可视化
- **作者贡献分析** - 开发者贡献度和活跃度分析
- **合并历史统计** - 合并请求和分支合并分析
- **文件变更统计** - 文件修改频率和类型分布
- **时间趋势分析** - 代码变更的时间序列分析
- **分支活跃度** - 各分支的提交活跃度对比

### 🎨 可视化图表
- 提交时间线散点图
- 作者贡献饼图
- 代码行数变化趋势图
- 文件类型修改分布树状图
- 合并频率柱状图
- 分支活跃度横向柱状图
- 提交活跃度热力图

### ⚙️ 高级功能
- 灵活的时间范围筛选（最近7天/30天/90天/一年/自定义）
- 多分支分析支持
- 实时数据更新
- 响应式Web界面
- 数据导出功能

## 安装和使用

### 环境要求
- Python 3.8+
- Git

### 安装步骤

1. **克隆或下载项目**
   ```bash
   # 如果这是一个Git仓库
   git clone <repository-url>
   cd ai-submitter
   ```

2. **安装依赖**
   ```bash
   pip install -r requirements.txt
   ```

3. **运行应用**
   ```bash
   streamlit run app.py
   ```

4. **访问应用**
   - 打开浏览器访问：http://localhost:8501

### 使用说明

#### 1. 仓库分析流程

1. **启动应用**
   - 通过 `run.bat` / `run.sh` 或 `streamlit run app.py` 启动服务
   - 终端中会显示访问地址（默认 http://localhost:8501）

2. **选择 Git 仓库来源**
   - 保持默认值 `.` 可直接分析当前目录
   - 输入本地绝对路径（例如：`/Users/alice/project`）可分析任意本地仓库
   - 输入远程地址或 `owner/repo` 简写会自动进行临时克隆，支持 GitHub/GitLab/Bitbucket
   - 选择历史记录中的路径可以快速切换常用仓库

3. **配置分析参数**
   - 在侧边栏设置时间范围（最近 7/30/90 天或自定义日期区间）
   - 指定目标分支，或选择“全部分支”查看整体趋势
   - 勾选是否统计合并提交、文件变更、代码行变动等高级指标

4. **查看分析结果**
   - 顶部选项卡涵盖提交、作者、时间、分支、文件等多维图表
   - 图表支持缩放、悬停提示与导出 PNG/CSV
   - 面板中的指标卡会根据筛选条件即时更新

5. **导出与复用**
   - 将关心的图表下载成图片或数据表，方便撰写周报/复盘材料
   - 复制页面右上角的分享链接，可快速保存当前筛选状态

#### 2. GitHub PR/MR 管理模块

1. **准备 GitHub Personal Access Token**
   - 登录 GitHub，访问 [Settings ➜ Developer settings ➜ Personal access tokens](https://github.com/settings/tokens)
   - 生成一个 classic token，勾选 `public_repo`（公开仓库）或 `repo`（包含私有仓库），建议额外勾选 `user`

2. **在应用中配置 Token**
   - 打开“MR 管理”选项卡，按提示输入 token 并保存
   - 系统会校验连通性与权限，不通过时会给出 Troubleshooting 建议

3. **选择要管理的仓库**
   - 支持 `owner/repo`、`https://github.com/owner/repo(.git)` 等格式
   - 可以设置最近 N 天（1-90）的时间窗口和 PR 状态（all/open/closed）

4. **同步并查看数据**
   - 点击“刷新 PR 数据”后会：
     1. 校验仓库访问权限
     2. 调用 GitHub API 获取 PR 列表及增删行、改动文件等指标
     3. 将结果存入 `mr_data.db`，供后续 review、审批历史查询

5. **后续操作**
   - 在界面中查看 PR 详情、评审记录与操作日志
   - 自定义“操作人名称”后，审批/记录会带上操作者身份，便于团队协作追踪

#### 3. 常见使用场景
- **个人周报/绩效复盘**：按时间过滤自己的分支，导出作者贡献和提交活跃度
- **团队例会展示**：将远程仓库地址填入，快速获取公共项目的核心指标
- **PR 审核看板**：配置 token 后集中查看目标仓库的 PR 进度、风险等级与处理历史

## 故障排除

### 常见问题

1. **"不是有效的Git仓库"错误**
   - 确保路径指向包含 `.git` 文件夹的目录
   - 检查路径是否正确

2. **数据加载缓慢**
   - 大型仓库分析可能需要较长时间
   - 建议使用时间范围筛选减少数据量

3. **图表显示异常**
   - 检查网络连接
   - 刷新页面重试

### 性能优化建议

- 对于大型仓库，建议使用较短的时间范围
- 定期清理浏览器缓存
- 确保有足够的系统内存
